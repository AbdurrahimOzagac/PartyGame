# ShooterParty architecture

ShooterParty is a 4-player party game made of mini-games. Every mini-game uses the same cube critters and the same spit shot. Knockback Arena is the first mini-game and the worked example for new ones.

- Unity 6000.3.9f1, URP, Input System.
- Netcode for GameObjects (NGO) 2.13, Unity Transport (UTP) 2.7.4. UDP for Local and Practice, WebSockets for online play.
- Related docs: [ADDING_A_MINIGAME.md](ADDING_A_MINIGAME.md) (step by step) and [SERVER_OPS.md](SERVER_OPS.md) (deploy and run the server).
- Background: the design spec `projects/shooterparty/specs/2026-10-24-shooterparty-basis-design.md`. Where this doc and the spec disagree, this doc follows the code.

## 2. Processes and network

```
 Player's game (macOS / Windows / Linux)
   │ 1. HTTPS  partyshooter.ezellm.com/api/v1/...   create room / join by code  -> ticket + wsUrl
   │ 2. WSS    partyshooter.ezellm.com/g/1|2        lobby, rounds, results (NGO over UTP WebSocket)
   │           (UTP connects to WssBridge on 127.0.0.1; the bridge does TLS to Cloudflare)
   ▼
 Cloudflare edge ── tunnel "partyshooter" (cloudflared-partyshooter.service)
   ▼
 Server (Linux ARM64), every listener on 127.0.0.1
   ├─ room service       :7700  /api/   room_service.py, Python standard library only
   │                     :7709         detailed status, NOT routed by the tunnel
   ├─ game server slot 1 :7701  /g/1   headless Unity, one process per room, started by the room service
   └─ game server slot 2 :7702  /g/2   (2 rooms at most)
```

One build runs in several modes (`PartyMode`, started by `PartyNet`):

| Mode | Started by | Transport | Tickets | Notes |
|---|---|---|---|---|
| `OnlineClient` | menu: PLAY ONLINE > CREATE ROOM / JOIN ROOM, via `JoinFlow` | UTP WebSocket → `WssBridge` → `wss://` | yes | needs the room service |
| `DedicatedServer` | the room service: `-party-server -slot N -port 77xx -wsPath /g/N -room CODE ...` | plain `ws` on 127.0.0.1 | checks them | `ServerRuntime`; secret from `PARTY_TICKET_SECRET` |
| `LocalHost` / `LocalClient` | menu: SAME WI-FI > HOST / JOIN BY ADDRESS | UDP 0.0.0.0:7777 | no | same Wi-Fi, no internet; no rejoin |
| `Practice` | menu: PRACTICE VS BOTS | UDP 127.0.0.1, ephemeral port | no | you + 3 bots, `minPlayers` 1; the default way to test a mini-game |

`Bootstrap` (in `SP_Boot`) reads the command line: `-party-server ...` runs `ServerRuntime`, `-autopilot ...` runs `Autopilot` (a self-playing client for tests), anything else loads the menu.

**Online join, step by step** (`JoinFlow`, `RoomServiceClient`):
1. `POST /api/v1/rooms` or `POST /api/v1/rooms/{code}/join` with header `X-ShooterParty-Version` (`PartyProtocol.Version`, now 1). A mismatch returns 426, shown as "Update your game".
2. The reply holds `wsUrl`, a signed `ticket` (60 s, single use) and a `rejoinToken` (kept in memory only).
3. `PartyNet.JoinOnline` starts `WssBridge` and connects. The ticket travels in NGO's connection payload (`JoinPayload`).
4. On the game server, `ConnectionGate.Approve` checks version, signature, expiry, room code, name and single use, then `SessionFlow.CanJoin` checks capacity and phase.

**Why `WssBridge`:** stock UTP writes `Host: <IP:port>` in its WebSocket handshake, and Cloudflare answers 403. UTP also prefers IPv6. The bridge listens on 127.0.0.1, resolves IPv4 first, does TLS with the real hostname (SNI, system CAs), rewrites the `Host` line and then pipes bytes untouched. It also counts bytes for the F3 overlay. Dev flags: `-netDelay <ms>` adds latency, `-bridge` forces the bridge for plain `ws://` URLs.

**Stdout protocol** (game server → room service, one line each, see `ServerRuntime`): `@@READY`, `@@STATE {phase, humans, connected, pids}` on change, `@@STATS {tickMs, tickMsMax, players, rttAvgMs}` every 10 s, `@@RESULT {totals, rankings}` at the Final, `@@END`. A game server exits when a finished session's players all left on purpose (not after a drop: they are rejoining), after 60 s with nobody connected, after 30 min idle in the lobby, or after 2 h (`ServerRuntime.ExitReason`).

## 3. Who decides what

Own movement is owner-authoritative, because NGO has no rigidbody prediction and server authority would add ~200 ms to your own movement at the measured ~150 ms RTT. Everything that changes the game's outcome is server-authoritative.

| Thing | Simulated by | Decided by | Synced by |
|---|---|---|---|
| Your critter's movement, jump, dash, facing | owner client (`CritterMotor`, dynamic rigidbody) | owner; the server runs `SpeedCheck` on owner timestamps (logs above the cap, kicks only at > 3× the cap for 2 s) | `CritterNetworkTransform` (Owner authority) + `NetworkRigidbody`; other copies are kinematic proxies |
| Bots, and the host's own critter in Practice/Local | server | server | same transform |
| Dash and jump charges | owner | owner; the server only grants pickup charges (`NetworkCritter.ServerAddJumpCharge`) | not synced |
| Firing | owner shows a cosmetic blob at once | server, in `ShotSystem.ValidateAndFire`: token bucket (6/s, burst 12), cooldown on the client's timestamps, origin clamped to the server's muzzle if implausible | `FireRpc` (Owner-only) → `BlobSpawnedRpc` |
| Hits | server's physical blob (`SpitBlob`) | server, then `ShotEffect.ApplyServer` | `BlobHitRpc`, `BlobSplatRpc` |
| Knockback and mass | server computes Δv with the server's mass | server (`ShotContext.Knock`) | `KnockbackRpc(blobId, Δv, newMass, epoch)` to the victim's owner, which *sets* the mass; `NetworkCritter.Mass` for HUDs |
| Elimination, in-game score, round ranking | server | the mini-game's `MiniGameController` | `NetworkCritter.Eliminated`, `SessionManager.Players` |
| Crown | server | `ScoreRules.NextCrown` | `SessionManager.CrownSlot` |
| Pickups | server trigger | server | `NetworkVariable` on the pickup (`JumpPickup`) |
| Lobby: seats, ready, colour, playlist, kick, start | server (`SessionFlow`) | server; clients ask with `SessionManager.Request*` | `SessionManager` network variables and lists |
| Room codes, tickets, slots | room service | room service | HTTP |
| Critter-critter contact | nobody | off (`Physics.IgnoreCollision` between all critters) | n/a |
| FX, sounds, HUD | every client | nobody (cosmetic) | one-shot actions via `ActionRpc` relayed by the server |

Cosmetic blobs never decide anything. They pass through critters and stop only on world geometry or when the server's hit event arrives. Knockback events carry the round **epoch** (`SessionManager.Epoch`, copied to `NetworkCritter.Epoch`), and the owner drops events from an older round.

## 4. Session flow

`SessionFlow` holds the rules as a plain C# state machine (tested on a fake clock). `SessionManager` runs it on the server and mirrors it into network variables for clients.

```
Lobby ─Start─▶ Loading ─scene loaded─▶ Intro 4 s ─▶ Countdown 3 s ─▶ Playing ─EndRound─▶ RoundResults 6 s
   ▲                                                                                        │
   │                                       more games? ◀── Standings 6 s ◀──────────────────┘
   │                                         │yes → Loading (next game)
   └──────────── Final 12 s (in SP_Lobby) ◀──┘no
```

- **Playing** ends when the controller calls `EndRound()` or the timer (`MiniGameDefinition.durationSeconds`) runs out.
- **Lobby rules:** the creator is the leader (star). The host leads in Local and Practice. If the leader leaves, the longest-present connected human leads. The leader picks a preset or builds a playlist (1-10 games, repeats allowed, name ≤ 24 chars, ids checked against the catalog), toggles "Replace leavers with bots", kicks (lobby only), and starts.
- **Start needs:** the leader, at least `minPlayers` connected humans (3 online and Local, 1 in Practice), every other human ready, and a playlist. `SessionFlow.StartBlocker` returns the reason, and the lobby shows it above the button.
- **Presets** live on the catalog (`MiniGameCatalog.presets`): Quick (3), Classic (5), Marathon (8). They cycle through all catalog games, so they change when a mini-game is added. A new room opens on the first preset.
- **Scoring:** `RankPlayers()` gives a ranking with shared ranks ("1, 2, 2, 4"). `ScoreRules.Award` turns it into points from `placementPoints` (default 4/3/2/1). The table is read from the top, so 3 players get 4/3/2, and tied ranks share the higher value. The session total is the sum.
- **Champion:** `ScoreRules.Champions`: highest total, then more round wins, then the better last-round rank, otherwise shared. Only `eligible` seats count. A seat stops being eligible on a clean leave, or 60 s after a drop if the player did not come back.
- **Crown:** during a round, the top in-game score wears it. Nobody wears it at 0, and a tie keeps the current wearer. It is shown on the critter (`CrownView`, `LeaderCrown` on the "Top" bone) and on the HUD card. An eliminated wearer keeps the HUD icon only.
- **Disconnect mid-round** counts as a fall at that moment (`MiniGameController.ServerPlayerLeft`). The seat and points are held for 60 s (`SessionFlow.RejoinGraceSeconds`). In the lobby, a drop frees the seat.
- **Rejoin (online only):** when the reason is "Connection lost", `JoinFlow` calls `/rooms/{code}/rejoin` with the `rejoinToken` (backoff 1, 2, 4, 8, 8 ... s, for up to 60 s). Rejoin is never by name. A rejoiner spectates until the next round.
- **Bot takeover:** with "Replace leavers with bots" on, a bot drives a disconnected human's seat **from the next round's load**. If the human rejoins, they drive the seat again from the next round.
- **Too few humans:** if fewer than `min(2, minPlayers)` humans remain mid-session, the session jumps to the Final. A dropped human still counts during the 60 s grace, so a tunnel blip that drops everyone at once does not end the session (`e2e_local.sh drop-all`).
- **After the Final:** back to the Lobby, ready flags reset, disconnected humans and the bots that stood in for them removed. Starting again needs `minPlayers` again.

## 5. Scene flow

```
SP_Boot ──▶ SP_Menu ──(start a mode)──▶ SP_Lobby ◀──▶ mini-game scene (e.g. KnockbackArena_Ice)
   │            ▲                          │
   │            └──── leave / disconnect ──┘   (UiRoot loads SP_Menu)
   └─ Persistent: UI_Root, Sfx, EventSystem; PartyNet (+ NetworkManager, UnityTransport) + Bootstrap
```

- `SP_Boot` is build scene 0. Its `Persistent` object keeps `UI_Root` (one canvas for the whole run), `SfxPlayer` and the `EventSystem` across loads. `PartyNet` is `DontDestroyOnLoad`.
- On server start, `PartyNet` spawns its `serverSingletons`: `Net_ShotSystem` and `Net_SessionManager` (both under `Assets/ShooterParty/Core/Prefabs`). They live across scene loads.
- `SessionManager` loads every scene with NGO's `NetworkSceneManager` in Single mode. Before each load it despawns the mini-game controller and every critter. If a load is requested while another scene event runs, it is queued.
- When a mini-game scene has loaded on all clients (or they timed out), `SessionManager` spawns the definition's `controllerPrefab` and calls `ServerSetupRound()`. The controller spawns one critter per seat at the `MiniGameScene` spawn points, plus pickups.
- The Final plays in `SP_Lobby`: `LobbyStage` swaps the pedestals for the `Podium_Ice` podium.
- A scene that NGO loads must be in the build settings. Mini-game scenes hold no NetworkObjects.

## 6. UI

- **`UiRoot`** (`Scripts/UI/UiRoot.cs`) is the single canvas. Offline it shows `MenuScreen`. In a room it shows each `SessionView` whose `ShowsIn(phase)` is true, and hides the rest. Modals sit on top.

| Phase | View |
|---|---|
| Lobby | `LobbyView` (seat cards, party code or host IPs, `PlaylistBuilder`, options) |
| Loading | loading curtain ("Loading Knockback Arena…") |
| Intro | `IntroCard` (name, tagline, `howToPlay`, `controlsHint`, icon, round x of n) |
| Countdown, Playing | `PartyHud` (`HudCard` per seat, timer, crosshair + cooldown ring, dash pips, jump slot, OUT banner, spectate label) + the mini-game's widget |
| RoundResults | `RoundResultsView` |
| Standings | `StandingsView` |
| Final | `FinalView` (with the podium in `LobbyStage`) |

- Always available: `NameCodeDialog`, `JoinProgressView`, `Dialog`, `SettingsView` (stored in PlayerPrefs via `GameSettings`), `PauseMenu`, `Toasts`, `NetStatsOverlay` (F3).
- **Views only read and request.** They read `SessionManager`, the current `MiniGameController` and `NetworkCritter` state, and call `SessionManager.Request*`. They never decide rules.
- **Controls:** `LocalCritterInput` drives the local critter; `OverShoulderCamera` and `UiRoot` handle the camera and mouse capture. Read those files for the current bindings; this doc does not list keys.
- **Built from code.** `ShooterPartySetup.BuildAll` (menu **ShooterParty > Rebuild core assets**) runs `UiBuilder.BuildUiRoot`, which calls `LobbyBuilder.BuildLobbyView` and `HudBuilder.BuildHud` / `BuildIntro` / `BuildResults` / `BuildStandings` / `BuildFinal`. It saves `Prefabs/UI_Root.prefab` and regenerates `SP_Menu`, `SP_Lobby` and `SP_Boot`. Hand edits to those files are lost on the next rebuild: change the builder instead. `UiKit` has the shared palette (`Ink`, `Teal`, `Tomato`, `Violet`, `Chartreuse`, ...), the Fredoka fonts and the helpers (`Panel`, `Btn`, `T`, `I`, `R`).
- The lobby's "+ GAME" buttons are baked from the catalog at build time. Rebuild core assets after adding a mini-game.

## 10. Rules that keep it secure

The repo is public and the server is on the internet. Follow these when you add code.

1. **The server decides results.** Clients send intents (`FireRpc`, `SessionManager.Request*`), never results. Do not add RPCs like "set my score", "I eliminated X" or "my mass is".
2. **Never trust a client RPC.** Check the phase, the round epoch, leadership, and that every vector is finite. Check lengths before you parse (`SessionManager.PlaylistRpc` caps the name at 64 chars and the list at 400) and ids against the catalog.
3. **Set RPC permissions explicitly.** Owner → server: `[Rpc(SendTo.Server, InvokePermission = RpcInvokePermission.Owner)]` on an object the sender owns, so nobody can act for someone else. Server → clients: `InvokePermission = RpcInvokePermission.Server`. NGO's default lets any client invoke. A server-owned object that takes requests from everyone (like `SessionManager`) must find the sender from `RpcParams.Receive.SenderClientId`, never from an argument.
4. **Rate-limit per client** with `TokenBucket` (requests: 20/s, burst 40; fire: 6/s, burst 12). Drop the excess and log it.
5. **Text from players goes through `NameRules`.** It rejects `<` and `>`, so nobody can inject TextMeshPro rich text into other players' HUDs.
6. **No NetworkObjects in scenes.** The server spawns everything at runtime.
7. **No secrets or infrastructure in git:** no IPs, hostnames, user names, keys or tickets. The ticket secret exists only on the server (`/etc/partyshooter/secret`). Use placeholders like `<ssh-host>`.
8. **Keep the server's surface small.** Every listener binds 127.0.0.1, and the tunnel routes only `^/api/`, `^/g/1$` and `^/g/2$`. A new endpoint needs a reviewed change to the room service and the tunnel config.
